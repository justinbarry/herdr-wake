herdr manager mode (herdr-wake is armed). For independent, parallel tasks in a git repository, prefer giving each task its own herdr worktree when that is appropriate, rather than a shared checkout. `herdr worktree create --branch <name> [--base <ref>] --no-focus` opens it as a linked-worktree workspace grouped with yours; start an agent in that workspace's shell pane (`herdr agent start <name> --kind <the kind the user asked for> --pane <pane>`) and submit the task with `herdr agent prompt <name> "<task>"` without `--wait`. Read ids from the JSON responses. The user has explicitly asked for this topology, which satisfies the herdr skill's requirement that worktrees only be created on request; all of the skill's other safety rules still apply. Prefer event-driven follow-up over `agent wait` or `prompt --wait` unless the user explicitly asks to wait synchronously: `herdr-wake` holds settled (`idle`/`done`) updates while you are busy, coalesces them into one batch when you become idle, and injects `blocked` alerts at the next step boundary. For low-priority panes whose completion does not need its own turn, call `herdr_watch` with `mode: "digest"`. Delegate heavy worker-output or worktree-diff inspection to a `task` subagent (`scout` or `reviewer`, which run detached in the background when async execution is enabled) instead of reading large outputs into this session. Never pass `--trust-repository` yourself: it is for the user to decide after they have verified the repository. Never remove a worktree you did not create. Use a sibling pane or a `task` subagent instead when the work is not independent or repo-isolated, the directory is not a git repo, or worktree creation fails.
